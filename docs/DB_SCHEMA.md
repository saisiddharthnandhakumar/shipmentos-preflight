# Database schema (Neon PostgreSQL)

Defined in `lib/db/schema.ts`; versioned SQL migrations in `drizzle/` (generated by Drizzle Kit, committed, applied with `npm run db:migrate` over the **direct** connection). The app uses the **pooled** URL through `drizzle-orm/node-postgres` + `pg.Pool` (interactive transactions supported) with `attachDatabasePool()` for Vercel Fluid compute.

## Tables

| Table | Key columns | Notes |
|---|---|---|
| `anonymous_sessions` | `id uuid pk`, `token_hash text unique`, `created_at`, `last_seen_at`, `expires_at` | Only the SHA-256 hex digest of a 256-bit random token. Sliding 7-day expiry. Deleting a session cascades to everything it owns. |
| `import_batches` | `id`, `session_id → sessions (cascade)`, `original_filename_sanitized`, `booking_row_count`, `item_row_count`, `status`, `summary jsonb` | One row per upload. No workbook bytes. |
| `bookings` | `id`, `session_id → sessions (cascade)`, `import_batch_id → import_batches (cascade, nullable)`, `source chat|excel`, `create_request_id`, `external_booking_id`, `title`, canonical booking columns, `revision int`, `status`, `red_count`, `amber_count`, `message_count`, `source_row`, `raw_row jsonb`, `confirmed_at`, `confirmed_revision`, `created_at`, `updated_at`, `last_activity_at` | One chat thread = one `source=chat` booking. Money/weights `numeric(14,4)`; ready date SQL `date`. `external_booking_id` (e.g. `BK-001`) is **not** globally unique. |
| `booking_items` | `id uuid pk` (stable item id used by patches), `booking_id → bookings (cascade)`, `position`, item columns, `source_row`, `raw_row jsonb` | HS code stored as text (leading zeros preserved). `''` = explicitly blank, `NULL` = not yet known (chat). |
| `chat_messages` | `id`, `seq bigint identity`, `booking_id → bookings (cascade)`, `session_id → sessions (cascade)`, `role user|assistant|event`, `content`, `request_id`, `revision`, `meta jsonb`, `created_at` | Transcript replay orders by `seq`; pagination cursor = `seq`. Excel bookings never get messages. |
| `chat_turn_requests` | `id`, `booking_id → bookings (cascade)`, `request_id`, `kind chat|edit|confirm`, `expected_revision`, `applied_revision`, `response_json jsonb` | **Unique `(booking_id, request_id)`**: a retried request returns the stored response and never re-applies (e.g. "add one pallet" increments once). |
| `booking_revisions` | `id`, `booking_id → bookings (cascade)`, `revision`, `source create|chat|edit|import|confirm`, `change_patch jsonb`, `changed_fields jsonb`, `before_json`, `after_json` | **Unique `(booking_id, revision)`**. Audit trail, e.g. pallets 3 → 4. |
| `evaluations` | `id`, `booking_id → bookings (cascade)`, `booking_revision`, `engine_version`, `rate_card_version`, `rulebook_version`, `today_uk`, `status`, counts, `findings jsonb`, `carrier_snapshot jsonb`, `missing_fields jsonb`, `input_issues jsonb`, `result jsonb` | **Unique `(booking_id, booking_revision)`**. Version tags make a stale snapshot impossible to mistake for the current one. |
| `import_issues` | `id`, `batch_id → import_batches (cascade)`, `booking_id → bookings (set null)`, `sheet`, `source_row`, `column_name`, `issue_code`, `severity error|warning|info`, `message`, `raw_value` | Structural/input problems, kept separate from R-01…R-10. |
| `carrier_options` | `key text pk` (`GB-DE-A` …), carrier, service, route, `price_per_pallet_gbp numeric(10,2)`, `transit_days`, `on_time_percent`, `max_kg_per_pallet`, `rate_card_version` | Exactly 9 rows from the workbook; seeded idempotently; runtime refuses to evaluate on fixture mismatch. |
| `rule_definitions` | `rule_id pk`, `description` (verbatim), `severity Red|Amber`, `rulebook_version` | Exactly 10 rows. Rule logic lives in TypeScript (`lib/domain/rules.ts`), not SQL. |

## Indexes

- `bookings (session_id, last_activity_at desc, id desc)` — Booking History.
- `bookings (session_id, source, last_activity_at desc, id desc)` — Previous chats (`source='chat'`).
- `bookings (session_id, create_request_id)` unique where not null — idempotent thread creation.
- `chat_messages (booking_id, seq)` — ordered transcript pagination.
- `booking_items (booking_id, position)`, `import_batches (session_id, created_at)`, `import_issues (batch_id)`, `anonymous_sessions (expires_at)`.

## Write path (one chat turn or direct edit)

All in one `BEGIN … COMMIT`:

1. `INSERT chat_turn_requests … ON CONFLICT (booking_id, request_id) DO NOTHING` → if it already exists, return the stored `response_json` (replay).
2. `UPDATE bookings SET …, revision = revision + 1 WHERE id = $id AND session_id = $session AND revision = $expected` → 0 rows ⇒ HTTP 409.
3. Delete removed items; upsert remaining items by stable id.
4. Insert user + assistant messages (chat only).
5. Insert `booking_revisions` and `evaluations` for the new revision.
6. Store the response on the turn request.

Any exception rolls back every step; the client shows "Unable to save; retry" and nothing is marked saved.

## Ownership

Every repository function takes the cookie-resolved `session_id` and filters by it (`lib/db/repo.ts`). Unknown, malformed or foreign booking IDs all return 404.

## Retention

Anonymous sessions expire 7 days after last activity. Expired sessions can no longer read anything. Physical deletion is best-effort on access (each new session creation deletes up to 50 expired sessions, cascading to their data) plus the explicit "Reset my data" (`DELETE /api/session`). No background cron is installed.
